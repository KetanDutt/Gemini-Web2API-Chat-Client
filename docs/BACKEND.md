# The bundled Gemini Web2API backend

GlassGem ships with a vendored copy of
[**gemini-web2api**](https://github.com/ikhsan3adi/gemini-web2api) (by
[@ikhsan3adi](https://github.com/ikhsan3adi), Go) in
[`gemini-web2api-ikhsan3adi/`](../gemini-web2api-ikhsan3adi). This directory is
the backend GlassGem talks to: it converts Google Gemini's web interface into
an OpenAI-compatible local API (`/v1/chat/completions`, `/v1/models`,
`/v1/responses`, `/v1beta/models`) with streaming, tool calling, vision upload
and TLS impersonation.

Keeping the sources in the repo means **a working backend is always one build
away** — no separate clone step, pinned to a version GlassGem is tested
against, and patchable where the integration matters (see
[Local modifications](#local-modifications-vs-upstream)).

## How GlassGem uses it

Every entry point funnels through [`scripts/ensure-web2api.mjs`](../scripts/ensure-web2api.mjs):

```
run.bat / run.sh / run-desktop.bat / npm run dev / npm run web2api
        │
        ▼
scripts/ensure-web2api.mjs
  1. already answering on :8081?             → reuse it
  2. WEB2API_DIR set?                        → use it (strict)
  3. gemini-web2api-ikhsan3adi/ has sources? → use the bundled copy  ◄── default
  4. legacy gemini-web2api/ checkout nearby? → reuse it
  5. none found?                             → git clone (optional)
  6. binary missing?                         → go build, else verified
                                               prebuilt download
  7. write default config.json if missing    → API key sk-gemini
  8. start detached daemon, wait for /v1/models
     (desktop sessions: session-scoped daemon, stopped with the session)
  9. everything failed?                      → clearly labelled MOCK
```

- The daemon survives GlassGem restarts by design; stop it with
  `npm run web2api:stop` (or `run.bat stop` / `./run.sh stop`).
- **Desktop sessions are the exception:** `run-desktop.bat`, `desktop.bat dev`
  and `npm run desktop:dev` start the daemon *session-scoped* — attached to
  the same terminal/console as the app. Closing the Electron window stops it
  automatically (via `scripts/desktop-dev.mjs`), and Ctrl+C or closing the
  terminal stops it with the session (the OS delivers the console/terminal
  event to every attached process, on Windows and Unix alike). A server that
  was already running beforehand (`npm run web2api`, a system service) is
  detected via the pid file and left untouched.
- While a daemon recorded in `.web2api.pid` is still alive but not answering
  (slow boot), a second ensure call **waits for it instead of spawning a
  duplicate** — the pid file always points at the real server, so it stays
  stoppable.
- Server output goes to `.web2api.log`, the pid to `.web2api.pid` (both
  project root, gitignored).
- Set `GLASSGEM_SKIP_AUTO_WEB2API=1` to manage the server yourself (Docker,
  another machine…) and `GLASSGEM_WEB2API_URL` / `GLASSGEM_WEB2API_PORT` to
  point at a different address. GlassGem honors that port when it starts the
  server itself.
- `sudo sh setup-linux.sh` registers the same pipeline as system services on
  both init systems: systemd units (`gemini-web2api.service`) or OpenRC
  scripts (`/etc/init.d/gemini-web2api` on Alpine/Gentoo); both use
  `scripts/start-web2api.sh`, which prefers the vendored directory too. The
  whole pipeline is POSIX-`sh` and BusyBox-ready, so **Alpine Linux works
  with no extra shell installed**.

### Platform support of the generated binary

`go build` runs with `CGO_ENABLED=0` (both in `ensure-web2api.mjs` and in the
service scripts): the module is pure Go, so the produced binary has **no libc
dependency** and runs unchanged on glibc and musl (Alpine) systems. The
prebuilt release download produces glibc binaries — on Alpine they only work
with `gcompat` installed, so there GlassGem prefers building from source
(via `apk add go`, which the setup script can install for you); the
`--version` sanity probe discards an incompatible download automatically.

## The backend in 60 seconds

From the vendored README (see `gemini-web2api-ikhsan3adi/README.md` for the
full manual, and `README.zh-CN.md` for 中文):

- **Runs anonymously** — no Google cookies needed for Flash models.
  `gemini-3.1-pro` *routes to Flash* without authentication; real Pro routing
  needs a Gemini Advanced cookie (`--cookie-file`, see the vendored README §
  "How to get cookies").
- **API keys**: when `api_keys` in `config.json` is non-empty, every `/v1/*`
  and `/v1beta/*` route requires `Authorization: Bearer <key>` (default
  generated by GlassGem: `sk-gemini`). An empty list means open access — keep
  it listening on localhost in that case.
- **Models** (resolved by `internal/models`): `gemini-3.7-flash`,
  `gemini-3.6-flash` (default), `gemini-3.5-flash(-thinking/-thinking-lite)`,
  `gemini-3.1-pro(-enhanced)`, `gemini-auto`, `gemini-flash-lite`. Append
  `@think=N` (0 deepest … 4 shallowest) to control reasoning depth, e.g.
  `gemini-3.6-flash@think=0`.
- **Vision**: images (`image_url`, base64 or remote) are uploaded via the
  Scotty resumable protocol with automatic client-side re-compression.
- **Tool calling** is supported in the OpenAI format (non-streaming path).
- **TLS impersonation** (`--impersonate chrome_120`, profiles `chrome_112`–
  `chrome_130`, `edge`, `safari`) helps behind aggressive WAFs.
- **Web search** is built in via Gemini's native grounding.

### Config (`config.json`)

GlassGem generates one inside `gemini-web2api-ikhsan3adi/` on first run from
`config.example.json` (your own edits are never touched). Keys, all optional:

| Key | Default | Purpose |
| --- | --- | --- |
| `port` / `host` | `8081` / `0.0.0.0` | Listen address. The CLI `--port` flag wins. |
| `api_keys` | `["sk-gemini"]` | Bearer keys; empty = no auth |
| `default_model` | `gemini-3.6-flash` | Fallback model |
| `retry_attempts` / `retry_delay_sec` | `3` / `2` | Upstream retry policy |
| `request_timeout_sec` | `180` | Upstream timeout |
| `gemini_bl` | pinned | Internal Gemini build label; refresh attempted at startup |
| `cookie_file` | – | Netscape/single-line cookie file for Pro routing |
| `proxy` | – | HTTP/SOCKS proxy for upstream calls |
| `impersonate` | – | TLS fingerprint profile |
| `temporary_chats` | `false` | Don't persist chats server-side |
| `auth_user` / `xsrf_token` | – | Multi-account index / page XSRF token (see vendored README) |
| `log_requests` | `true` | Access log line per request |

CLI flags: `--port`, `--config`, `--cookie-file`, `--proxy`, `--impersonate`,
`--version`.

### Docker alternative

Prefer containers? Build from the vendored directory:

```bash
docker build -t gemini-web2api ./gemini-web2api-ikhsan3adi
docker run -d --name gemini-web2api -p 8081:8081 gemini-web2api
```

Then start GlassGem with `GLASSGEM_SKIP_AUTO_WEB2API=1` so it talks to the
container instead of spawning its own daemon.

## Local modifications vs upstream

The vendored tree tracks upstream
[`ikhsan3adi/gemini-web2api`](https://github.com/ikhsan3adi/gemini-web2api)
with a small set of GlassGem integration patches. When refreshing the vendored
copy, re-apply (and re-test) these:

1. **Deterministic model listings** — `internal/models.SortedModelNames()`
   plus its use in `handleModels`, `handleGoogleModels`, `handleHealth` and
   the startup banner: Go map iteration made `/v1/models` return a different
   order on every call, which confused clients and snapshot tests.
2. **Stream errors reach the client** — `internal/server/chat.go` now emits an
   OpenAI-style `{"error": …}` SSE chunk when the upstream stream dies
   mid-response, instead of silently truncating the answer (GlassGem shows a
   real, retryable error with the partial text preserved).
3. **`.gitignore`** — also ignores `config.json` (GlassGem generates one in
   the checkout; your secrets stay local).
4. **Tests** — `internal/models/models_test.go` covers
   `SortedModelNames()`.

Refresh procedure: copy the new upstream tree over
`gemini-web2api-ikhsan3adi/`, re-apply the patches above, run `go test ./...`
and `go build ./...` in the directory, then `node scripts/ensure-web2api.mjs
--install-only` from the repo root.

## Backend development & tests

The vendored backend is a normal Go module (`go 1.26.5`, see its `go.mod`):

```bash
cd gemini-web2api-ikhsan3adi
go test ./...        # unit tests (config, format, models, multimodal, server)
go build -o gemini-web2api .
./gemini-web2api --port 8081
```

Without Go installed, GlassGem's launcher downloads the matching prebuilt
release binary (SHA-256 verified against the release `checksums.txt`) and
drops it into the vendored directory — `git status` stays clean because the
binary, `config.json` and `gemini-auth.json` are all ignored there.

## Security notes

- The server performs the sensitive part (Google cookies, fingerprinting)
  entirely in its own process; GlassGem (and its docs) never touch cookies.
- Keep `api_keys` configured when the server binds beyond localhost
  (`host: 0.0.0.0` is the upstream default so Docker/phone access works; it is
  unauthenticated to your LAN otherwise — set a key, or bind `127.0.0.1`).
- GlassGem's proxies only forward to loopback/private targets, so the UI can
  never turn the backend into an open relay. See [SECURITY.md](./SECURITY.md).
